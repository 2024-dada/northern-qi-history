# 分块与BM25接入说明

## 采用的分块原则

用户提出的“时间＋主题＋人物”作为每块的必备检索标签；实际切分以“一件事的一个连续语义段落”为边界。每块同时绑定事件ID、史料ID、书卷篇、原文定位和核验状态。

- 不同书、不同篇章的记载分开，不因人物与时间相同就合并。
- 同一事件可有经过、原文、项目分析、记载分歧等关联块；原文与分析明确分区或用不同text_type。
- 优先200—600汉字的自然段；这是初始目标，不是强制截断。短材料不凑字，长材料先保留父段再按语义拆分；否定词、人物指代、前因后果不要割断。
- 超长父段的子块可附上1—2句必要上下文，并记录重复上下文，不能当新增独立证据。
- 时间不详时写未知、区间或年号；不把《通鉴》附叙位置硬填成事件发生日。原书历法和现代公历分开。
- 人物按角色标记：下令者、执行者、受害者、信息提供者、仅被提及者；同名与别称另表维护。
- 文件名便于人看，稳定chunk_id用于程序引用。改标题时不随意改ID。

## BM25数据流（已接入；效果待评测）

用户原问题 → 本地问题解析/有限扩词 → BM25候选 → 事件/角色/问题类型重排 → 补回上下文及分歧 → 模型回答 → 引用具体块。

Markdown原文 → 核验与切块 → 统一JSON语料 → 中文词项与人名别称索引，与问题解析共同组成检索输入。

1. 收录阶段：以`03_索引/原文切块.json`作为唯一完整语料来源，生成前端与后端索引；文档保留source_id、chunk_id、原文、来源定位和核验状态。
2. 中文处理：检索前做NFKC和常用繁简字归一，中文按双字词切分，英文数字按词切分；展示原文保持不变。
3. 分字段评分：人物/别称4、主题3、时间1.5、书卷/篇章1.5、原文1。来源URL、JSON键名和项目解释不参与原典正文词频。
4. 初始参数k1=1.2、b=0.75；IDF、词频和平均长度从245个去重语义块计算。纯JavaScript完成，不需要Elasticsearch或外部服务。
5. 问题优化只在本地做确定性处理，不增加模型调用：识别列举、比较、原因、处置方式和正式法典等意图；删除常见口语填充词，保留用户原问题。人物与事件上下文只在追问代词或短追问时补入，读取最近一条用户问题，不用AI上轮答案当事实。
6. 关键词扩展用于提高召回，不改写问题事实。原问题词权重1，处置方式扩词约0.22，原因词约0.18；当前事件仅作辅助加权。正式法典/法条问题明确提示本站不是法律制度数据库。界面显示检索意图、扩展词和范围提醒。
7. 当前事件只作辅助加权，不能排除跨事件比较。一般问题最多回传4条事件卡、6个块；比较问题最多6条事件卡、10个块；列举问题最多8条事件卡、12个块；每事件至多带2个最相关原典候选块。
8. 没有关联事件卡的命中块仍可作为未归类原典候选传给模型，不据此推断具体事件。不同篇章和异文保持独立，不将重复摘要当多份证据。
9. 前端自备API和站长Worker使用同一份BM25源码及完整索引。模型提示区分项目整理与原文候选；界面显示实际命中的chunk_id和原典篇章链接。
10. BM25只负责排序和召回，不负责判定史实真伪，也不自动证明答案断言。当前还没有人工标注评测结果，不能宣称精度已实测提高。

## 验收题与判断标准

|问题|必须找回/表现|
|---|---|
|高德政为什么被杀？|经过与劝谏冲突；事后说法标为事后，不能冒充已证实动机|
|高洋说为诸元报仇，是真的吗？|原话归属与事后语境；不替人物认证内心|
|薛嫔是突然被杀的吗？|本纪、后妃传分别命中，指出时间叙述差异|
|兰陵王怎么死的？|高长恭别称命中，准确区分高纬与送药者|
|高孝琬是不是高纬杀的？|太上皇高湛责任与在位者区分|
|斛律光和高俨被杀有哪些区别？|两起事件均召回，不能只返回其中一个|
|那他为什么这么做？|结合前一轮指代，指代仍不明时澄清|
|蝎盆死了多少人？|该段未明确死亡，不编造数字|
|高洋有什么现代精神病？|不能据现有材料作诊断|
|某个资料库未收录的具体日期？|说明资料不足，不捏造答案|

先用旧检索和新检索回答同一批问题，记录正确证据召回率、排名、跨案例覆盖、异文覆盖及引用支持情况；未实际跑评测前，不宣称精度提升。
