# 分块与BM25接入说明

## 采用的分块原则

用户提出的“时间＋主题＋人物”作为每块的必备检索标签；实际切分以“一件事的一个连续语义段落”为边界。每块同时绑定事件ID、史料ID、书卷篇、原文定位和核验状态。

- 不同书、不同篇章的记载分开，不因人物与时间相同就合并。
- 同一事件可有经过、原文、项目分析、记载分歧等关联块；原文与分析明确分区或用不同text_type。
- 优先200—600汉字的自然段；这是初始目标，不是强制截断。短材料不凑字，长材料先保留父段再按语义拆分；否定词、人物指代、前因后果不要割断。
- 超长父段的子块可附上1—2句必要上下文，并记录重复上下文，不能当新增独立证据。
- 时间不详时写未知、区间或年号；不把《通鉴》附叙位置硬填成事件发生日。原书历法和现代公历分开。
- 人物按角色标记：下令者、执行者、受害者、信息提供者、仅被提及者；同名与别称另表维护。
- 文件名便于人看，稳定chunk_id用于程序引用。改标题时不随意改ID。

## 推荐的BM25数据流（尚未实现）

Markdown原文 → 核验与切块 → 统一JSON语料 → 中文词项与人名别称索引 → BM25候选 → 事件/角色/问题类型重排 → 补回上下文及分歧 → 模型回答 → 引用具体块。

1. 收录阶段：校验source_id、chunk_id、原文、来源定位和核验状态；缺字段报错，不能静默跳过。生成时保留语料版本及校验值。
2. 中文处理：繁简检索归一，但展示原文不改；完整人名/别称优先，搭配中文双字词作补充。处理“兰陵王/高长恭/高孝瓘”等已核别称。
3. 分字段评分：标题/主题、人物/别称、原文、项目概括分别评分；避免直接对JSON键名和来源网址计算词频。初始可用人物4、主题3、正文1的权重，必须通过评测调整，不能当最佳参数。
4. BM25初始参数可取k1=1.2、b=0.75；IDF、词频和平均长度均由实际语料计算。小规模语料可在JavaScript内直接评分，不必部署Elasticsearch。
5. 时间是过滤/辅助排序条件，不要求每个问题都有时间。名字精确命中、当前事件只能加权，不能排除跨事件问题。
6. 初始召回前12个候选，再按问题类型组织约4—6个块；比较题至少覆盖各比较对象，争议题必须补回关联异文。不要让同一事件的重复摘要挤满候选。
7. 没有充分命中时明确无站内依据；不能拿无关最高分凑答案。“他”一类追问需要结合最近对话与当前事件提取检索条件，不能只拿最新一句检索。
8. 回答每个关键历史断言绑定chunk_id；展示原文出处，区分检索到的材料与真正支持该断言的材料。链接存在检查不能替代语义支持核查。
9. 前端自备API与服务端站长API共用检索实现、资料版本和规则。原始资料仅在本地，本轮不自动上传完整本地目录；正式发布只导出所需且适合公开的数据。

## 验收题与判断标准

|问题|必须找回/表现|
|---|---|
|高德政为什么被杀？|经过与劝谏冲突；事后说法标为事后，不能冒充已证实动机|
|高洋说为诸元报仇，是真的吗？|原话归属与事后语境；不替人物认证内心|
|薛嫔是突然被杀的吗？|本纪、后妃传分别命中，指出时间叙述差异|
|兰陵王怎么死的？|高长恭别称命中，准确区分高纬与送药者|
|高孝琬是不是高纬杀的？|太上皇高湛责任与在位者区分|
|斛律光和高俨被杀有哪些区别？|两起事件均召回，不能只返回其中一个|
|那他为什么这么做？|结合前一轮指代，指代仍不明时澄清|
|蝎盆死了多少人？|该段未明确死亡，不编造数字|
|高洋有什么现代精神病？|不能据现有材料作诊断|
|某个资料库未收录的具体日期？|说明资料不足，不捏造答案|

先用旧检索和新检索回答同一批问题，记录正确证据召回率、排名、跨案例覆盖、异文覆盖及引用支持情况；未实际跑评测前，不宣称精度提升。
